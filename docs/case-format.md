# Case-study format

How to fill a case page with materials without changing code. Source of truth for the rules: `scripts/content/validate-case-data.mjs`; full example with all 15 blocks: [`tests/content/fixtures/case-example.json`](../tests/content/fixtures/case-example.json).

## Files

| File | Role |
| --- | --- |
| `content/cases.json` | Index of case routes. A case record: `id`, `purpose`, `file` (`cases/<id>.json`), `status` (`draft` or `publish`), `robots`. The `_foundation` record is the fixed technical route and has no file. |
| `content/cases/<id>.json` | The case: page text, approval, chapters and blocks. |
| `assets/cases/<id>/<name>-<width>.webp` | Generated images (widths 640, 1024, 1600, 2400; never wider than the source). |
| `styles/case-tokens.css` | Case-only text tokens (chapter intro). Loaded only by pages built from a case file. |

Routes: `/cases/<id>/` (FR) and `/en/cases/<id>/` (EN), generated by `npm run content:build`.

## Case file

```json
{
  "schemaVersion": 1,
  "id": "jane",
  "approval": { "en": false, "fr": false },
  "meta": { "pageTitle": { "en": "…", "fr": "…" }, "title": { "en": "…", "fr": "…" } },
  "chapters": [
    { "id": "identity", "title": { "en": "Identity", "fr": "Identité" }, "blocks": [ … ] }
  ]
}
```

- **Text** is always `{"en": "…", "fr": "…"}`. Line breaks (`\n`) are kept where a block shows them (prompt).
- **Bilingual, EN first.** `approval.en` is set to `true` when Kamila approves the English text; `approval.fr` cannot be `true` before it. A case is published only with both approvals and both languages in every text.
- **Chapter id** is latin kebab-case; it is the chapter's part of image names and its anchor on the page. Chapter order in the file is the order on the page and in the chapter menu.
- **Placeholder.** Any text, image, swatch or block may carry `"placeholder": true`. A draft may contain placeholders and empty French text.

## Images

```json
{ "src": "jane-identity-logo-horizontal", "alt": { "en": "…", "fr": "…" },
  "caption": { "en": "…", "fr": "…" },
  "crop": { "x": 0.4, "y": 0.1, "w": 0.2, "h": 0.2, "label": { "en": "…", "fr": "…" } } }
```

- Name: `<case>-<chapter>-<role>-<description>`, latin kebab-case, no extension, e.g. `jane-campaign-photo-basalt-movement`. The chapter must be the chapter that contains the image.
- `alt` is required; `caption` and `crop` are optional. `crop` is a fraction (0–1) of the image: a zoomed fragment with its label (used in `ai-episode`).
- Art direction: instead of `src`, `"art": {"horizontal": name, "vertical": name}` — the vertical frame on mobile, the horizontal one on wider screens. Approved pairs so far: studio close face, basalt movement.
- An image not chosen yet: `{"alt": {…}, "placeholder": true}` without `src`.
- Source photos are never modified; only images assigned to chapters are converted.

## Blocks

`L` = text `{en, fr}`; `I` = image; `I[]` = list of images. `?` = optional.

| Type | Fields |
| --- | --- |
| `hero-reveal` | `title` L, `subtitle` L?, `image` I, `facts` [{`label` L, `value` L}]? |
| `chapter-intro` | `text` L |
| `image-full` | `image` I |
| `image-pair` | `images` exactly 2 I |
| `image-row-3` | `images` exactly 3 I |
| `text-image` | `text` L, `image` I, `side` `"left"`/`"right"` |
| `logo-showcase` | `images` 1+ I, `text` L? |
| `palette-swatches` | `swatches` [{`name` L, `hex` `#rrggbb`}], `text` L? |
| `annotated-image` | `image` I, `notes` [{`x`, `y` 0–1, `text` L}] |
| `ai-episode` | `title` L, `problem` L, `before` 1+ I (with `caption`, `crop`), `method` L, `prompt` L?, `after` 1+ I; `placeholder`? |
| `sequence` | `images` 2+ I, `caption` L? |
| `detail-grid` | `items` [{`image` I, `text` L?}] |
| `principles-list` | `items` [{`title` L, `text` L}] |
| `outcome-montage` | `images` 3+ I, `text` L? |
| `chapter-menu` | no fields; at most once per case: the place where the sticky chapter menu starts |

## Checks: draft and publish

| Check | When | Fails on |
| --- | --- | --- |
| General (`validateCaseFormat`) | always: `npm run content:check`, `content:build`, so also before `npm test` and CI | broken structure: unknown block or field, wrong image count, name not kebab-case or wrong chapter, crop outside the image, FR approved before EN, a draft without `noindex` |
| Publication (`validateCasePublication`) | `content:check` for cases with `"status": "publish"`; on demand `npm run case:publish-check -- <id>` | any `placeholder: true`, any missing EN or FR text, missing approval, empty chapter, missing image file |

A draft (Jane now) therefore passes `content:check`, `npm test` and CI, and `case:publish-check` lists everything still missing. Tests: `npm run test:case-format`.

## Publishing a case

Only on Kamila's command: `npm run case:publish-check -- <id>` passes → set `"status": "publish"` and `"robots"` without `noindex` in `content/cases.json` → `npm run content:check` → `npm run content:build`.
