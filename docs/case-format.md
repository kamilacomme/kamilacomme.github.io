# Case-study format

How to fill a case page with materials without changing code. Source of truth for the rules: `scripts/content/validate-case-data.mjs`; full example with all 15 blocks (including an annotation over an SVG logo; `annotated-image` is deprecated): [`tests/content/fixtures/case-example.json`](../tests/content/fixtures/case-example.json).

## Files

| File | Role |
| --- | --- |
| `content/cases.json` | Index of case routes. A case record: `id`, `purpose`, `file` (`cases/<id>.json`), `status` (`draft` or `publish`), `robots`. The `_foundation` record is the fixed technical route and has no file. |
| `content/cases/<id>.json` | The case: page text, approval, chapters and blocks. |
| `content/cases/<id>.sources.json` | Source frame of each image name, relative to the case's source folder: `--source`, else `"sourceFolder"` in this file, else `~/Downloads/<id>` (Jane: `~/Downloads/Jane`). Only frames assigned to chapters. |
| `assets/cases/<id>/<name>-<width>.webp`, `images.json` | Generated by `npm run case:images -- <id>`: widths 640, 1024, 1600, 2400 not wider than the source, plus the source width when it is more than 10% wider than the largest step; never upscaled; WebP quality 80. `images.json` lists widths and intrinsic size. Sources are read only. An entry is a path, or `{"file": path, "crop": {x, y, w, h}}` (fractions of the frame) for a cropped copy; the original is never touched. |
| `styles/case-tokens.css` | Case-only text tokens (chapter intro). Loaded only by pages built from a case file. |

Routes: `/cases/<id>/` (FR) and `/en/cases/<id>/` (EN), generated by `npm run content:build`.

**Example page** (`content/cases/example.json`, id `example`): every block on real Jane frames (`example.sources.json` reads `~/Downloads/Jane`), neutral placeholder captions in EN and FR, for block prototypes. A noindex draft, not linked from the site, not in the project list; never published. It is not the test fixture (`tests/content/fixtures/case-example.json`, unchanged). Some layout issues are kept on purpose so `case:layout-check` shows them: a sketch in an image-full, a lone vertical, the two annotated-image blocks.

## Case file

```json
{
  "schemaVersion": 1,
  "id": "jane",
  "approval": { "en": false, "fr": false },
  "meta": { "pageTitle": { "en": "…", "fr": "…" }, "title": { "en": "…", "fr": "…" } },
  "chapters": [
    { "id": "identity", "title": { "en": "Identity", "fr": "Identité" }, "blocks": [ … ] }
  ]
}
```

- **Text** is always `{"en": "…", "fr": "…"}`. Line breaks (`\n`) are kept where a block shows them (prompt).
- **Bilingual, EN first.** `approval.en` is set to `true` when Kamila approves the English text; `approval.fr` cannot be `true` before it. A case is published only with both approvals and both languages in every text.
- **Chapter id** is latin kebab-case; it is the chapter's part of image names and its anchor on the page. Chapter order in the file is the order on the page and in the chapter menu.
- **Placeholder.** Any text, image, swatch or block may carry `"placeholder": true`. A draft may contain placeholders and empty French text.

## Rule: no text inside images

Applies to every case. Readable text (titles, captions, labels, logo version names, annotations) stays text in the case data, in both languages; an image stays an image. Do not use frames with text baked in: the English page would show French text, and the text could not be read by screen readers or translated. Logo versions are shown as SVG files in `logo-showcase`, their names as captions; a logo explanation is a frame of the SVG logo with plain text in the data (`annotated-image` is deprecated, see Blocks).

## Images

```json
{ "src": "jane-identity-logo-horizontal", "alt": { "en": "…", "fr": "…" },
  "caption": { "en": "…", "fr": "…" },
  "crop": { "x": 0.4, "y": 0.1, "w": 0.2, "h": 0.2, "label": { "en": "…", "fr": "…" } } }
```

- Name: `<case>-<chapter>-<role>-<description>`, latin kebab-case, no extension, e.g. `jane-campaign-photo-basalt-movement`. The chapter must be the chapter that contains the image.
- `span`: optional width in columns of the 12-column grid, see [Widths in columns](#widths-in-columns).
- `alt` is required; `caption` and `crop` are optional. `crop` is a fraction (0–1) of the image: a zoomed fragment with its label (used in `ai-episode`). A crop not marked yet: `{"placeholder": true}`.
- `format`: `webp` (default, generated from the source frame) or `svg` (vector art such as logos, copied unchanged from an `.svg` source to `assets/cases/<id>/<name>.svg`).
- `ratio` `"width:height"`: real proportions of a frame not delivered yet (`placeholder: true`), so the layout does not change when the file arrives. Jane logos: horizontal `1000:148`, main vertical `918:692`, sign `303:356` (from the PNG versions).
- `focus` / `focusMobile` `{x, y}` (0–1): the point kept in view when a frame is cropped to its cell (`object-position`); faces must not be cut. Default: centre.
- One frame belongs to one chapter (its name carries the chapter). Only `outcome-montage` may repeat frames of any chapter.
- Art direction: instead of `src`, `"art": {"horizontal": name, "vertical": name}` — the vertical frame on mobile, the horizontal one on wider screens. Approved pairs so far: studio close face, basalt movement.
- An image not chosen yet: `{"alt": {…}, "placeholder": true}` without `src`.
- Source photos are never modified; only images assigned to chapters are converted.

## Blocks

`L` = text `{en, fr}`; `I` = image; `I[]` = list of images. `?` = optional.

| Type | Fields |
| --- | --- |
| `hero-reveal` | `title` L, `subtitle` L?, `subtitleLong` L?, `subtitleShort` L?, `image` I, `facts` [{`label` L, `value` L}]? |
| `chapter-intro` | `text` L, `span`? |
| `image-full` | `image` I |
| `image-pair` | `images` exactly 2 I |
| `image-row-3` | `images` exactly 3 I |
| `text-image` | `text` L, `image` I, `side` `"left"`/`"right"`, `span`? (text column) |
| `logo-showcase` | `images` 1+ I, `text` L?, `span`? |
| `palette-swatches` | `swatches` [{`name` L, `hex` `#rrggbb`}], `text` L?, `span`? |
| `annotated-image` | **Deprecated** (contradicts the no call-outs rule; not used in Jane, kept on the example page until it is replaced). `image` I (raster or `"format": "svg"`), `notes` [{`x`, `y` 0–1, `textAt` {x, y}?, `text` L}]: markers at (x, y) as fractions of the block, so they hold at any width; with `textAt` a line joins the label to the marker |
| `ai-episode` | `title` L, `problem` L, `before` 1+ I (with `caption`, `crop`), `method` L, `prompt` L?, `refs` 1+ I? (reference images used for the fix; stored in the data, not rendered yet), `after` 1+ I; `placeholder`? |
| `sequence` | `images` 2+ I, `caption` L?, `span`? |
| `detail-grid` | `items` [{`image` I, `text` L?}] |
| `principles-list` | `items` [{`title` L, `text` L}] |
| `outcome-montage` | `images` 3+ I, `text` L?, `span`? |
| `chapter-menu` | no fields; at most once per case, the last block of its chapter: the sticky chapter menu starts there and lists the chapters after it |

## Widths in columns

The case page uses the site grid: desktop and tablet 12 columns, margins 32, gutter 24; mobile 4 columns, 16/16. A width is a number of columns, never a free size.

- **`span` on an image**: `3`, `4`, `6`, `8`, `12`, or `"bleed"` (full-bleed, only for the frame of an `image-full`). Not allowed in `hero-reveal` and `ai-episode`, which keep their own layout.
- **`span` on a block**: the width of its text column, `3`, `4`, `6`, `8` or `12`: `chapter-intro`, `text-image` (the text beside the image), and the text of `logo-showcase`, `palette-swatches`, `sequence`, `outcome-montage`.
- **Status:** the field is part of the data format and of `case:layout-check`; the block styles do not read it yet (part 1B of the blocks task).

Defaults without `span` (what the blocks do today, `DEFAULT_SPANS` in `scripts/content/case-layout.mjs`):

| Block | Default |
| --- | --- |
| `image-full` | `"bleed"` for a photograph whose source is 1600px wide or more; `12` for a drawing (role `sketch`) or a smaller frame; `6`, centred, for a vertical frame |
| `image-pair` | 6 + 6 |
| `image-row-3` | 4 + 4 + 4 |
| `text-image` | text 6 + image 6 |
| `chapter-intro` | text 8 |
| `sequence`, `detail-grid`, `outcome-montage`, `logo-showcase` | up to 4 frames in one row; 5–6 frames make rows of 3, 7 and more rows of 4; each frame 12 / frames per row |
| Text of `logo-showcase`, `palette-swatches`, `sequence`, `outcome-montage` | 6 |

**Mobile (proposal, not accepted yet):** on the 4-column grid `3` and `4` become 2 columns; `6`, `8` and `12` become 4; `"bleed"` stays full-bleed. Containers still decide: a block in a narrow column lays itself out as on a phone.

### Layout rules and `case:layout-check`

Role of a frame from its name (`<case>-<chapter>-<role>-…`): `sketch`, `scheme`, `error`, `detail`, `macro` are supporting frames; `photo` is a regular or final frame.

`npm run case:layout-check -- <id> [--json]` lists, block by block (chapter, block, frame, rule, what is wrong), every frame and text that breaks the rules below, using `span` or the default. It is a report only: it always exits 0 and is not part of `content:check`, `npm test` or CI.

| Rule id | Reported when |
| --- | --- |
| `aux-too-wide` | a supporting frame is wider than 6 columns or full-bleed (supporting frames are 3–4, at most 6) |
| `bleed-small` | a full-bleed frame is under 1600px wide |
| `bleed-count` | more than 4 full-bleed frames on the page |
| `row-sum` | the widths of a row (pair, row, text + image, a row of a multi-frame block) do not add up to 12 |
| `row-too-many` | more than 4 frames in a row |
| `row-four-not-aux` | four frames in a row that are not all supporting frames |
| `vertical-alone` | a vertical frame alone in the centre (an `image-full`); a vertical stays 3–4 columns in a row, 6 beside a 6-column text, or a 6 + 6 pair |
| `text-too-wide` | body text wider than 6 columns, a chapter intro wider than 8 |
| `annotated-image` | the deprecated block is used |

Not checked: `hero-reveal`, `ai-episode`, `chapter-menu`, the swatches and `principles-list` (own layout). Rules and tests: `scripts/content/case-layout.mjs`, `npm run test:case-format`.

## Chapter menu

- Markup: `scripts/content/case-render.mjs`; styles: `styles/case-content.css`; behavior: `scripts/case/chapter-menu.js` (sole owner). Loaded only by case pages that have a `chapter-menu` block.
- Sticky right under the fixed Navbar, inside the page gutters, on the page surface; no border lines and no numbers. Text: label token (12px, uppercase, 0.04em). Inactive chapters at 64% opacity (above 4.5:1); hover, keyboard focus and the current chapter at 100%. Tap targets 44px.
- Full row when every chapter title fits on one line (measured on the page, not a breakpoint); otherwise compact: one row with the current chapter and “Ouvrir / Open”, which opens the list below (closes on choice, Escape with focus back, click outside, focus leaving). Mobile is always compact with the Jane titles.
- The current chapter is the last one whose top has reached the menu (`aria-current="location"`). Chapter anchors (`#chapter-<id>`) land right under the menu.
- QA: `node tests/case/chapter-menu-check.cjs [report.json]` with `npm run test:serve` running: widths 320–1920 (step 40) at 900px height, iPhone 393×852 touch, iPad 820×1180 and 1180×820 touch, FR and EN.

## Block layouts

All 14 content blocks are built in a neutral classic layout, without polish (`scripts/content/case-blocks.mjs`, `styles/case-blocks.css`); the design pass comes after the content is in place. Page wrapper (replaceable without touching blocks): chapter sections and rhythm in `styles/case-content.css`, the chapter menu above, the case header in `styles/case.css`.

- **Container-based.** Each block is a CSS container (`container-type: inline-size`) and lays itself out from its own width, not the window's: a pair or row is one column below 30rem, two columns from 30rem, and a row of three or four frames gets one column per frame from 50rem. Proof: the same page in a 340px column on a 1440px screen stacks like a phone (`tests/case/blocks-check.cjs`). Exception: hero-reveal fills the first screen.
- **hero-reveal.** One frame from under the Navbar to the bottom gutter of the first screen (`100svh`), the vertical art-directed frame on portrait screens and the horizontal one on landscape. The case title (h1) comes from the block (`title`, else `meta.title`) and the plain case header is not added. The chapter title of the hero chapter is only for assistive technology.
- **image-pair.** Side by side from 30rem, same size cells (the first frame's proportions, 1:1 when orientations differ); stacked below, each in its own proportions. An art-directed frame shows its horizontal file in a wide container and its vertical file in a narrow one.
- **ai-episode.** Title (h3, project size), then Problem, Before, Method (with the prompt, line breaks kept) and After; the fixed labels are FR/EN in the renderer. Before and After are rows with the same size cells; a `crop` shows an enlarged detail under its frame with its label (a crop still `placeholder: true` is skipped).
- **Frames.** Cells crop their image (`object-fit: cover`) at the frame's `focus` (`focusMobile` in a narrow container), default `50% 35%`; faces must be kept in view by setting the focus. Images load lazily except the hero; `srcset`/`sizes` follow the layout.
- **Placeholders in a draft** render as quiet grey skeletons so the final layout is visible; the publication gate refuses them. A French text missing in a draft falls back to the English one, marked `lang="en"`.
- **Image quality rules.** A frame is never drawn wider than 1.15× its largest file: the block narrows and centres instead (`--cap`, shared by the cells of a row). Drawings (role `sketch` in the image name) are never full width: they stay inside a 64rem column, as does any `image-full` whose largest file is under 1600px; `image-full` goes full width only for photographs of 1600px or more. A row never has more than four frames: five and six make two rows of three, seven and eight two rows of four (one scheme for ai-episode rows, sequence, detail-grid and outcome-montage). `hero-reveal` is exempt from the stretch cap until Kamila decides on the 1200px frame.
- **chapter-intro.** Inter 400, 24px (20px on mobile), line 1.4, `--text-default`, up to 44rem wide; blank lines in the text make paragraphs.
- **image-full.** The grid's full width in the image's own proportions; a portrait frame is capped at 40rem wide and centred.
- **image-row-3.** Three same-size frames from a 40rem container, one per row below.
- **text-image.** Two columns from 40rem, image on the `side` given; stacked (text, then image) below.
- **logo-showcase.** Logos shown whole, centred on same-size quiet cells (4:3, auto-fit columns of 14rem or more); a logo not delivered yet is a skeleton in its real `ratio`. Optional text below.
- **palette-swatches.** Square swatches of the given hex (content, so the only coloured interface element), name and hex under each; auto-fit columns of 9rem or more.
- **annotated-image.** Markers at the given fractions of the image. From a 40rem container the labels sit over the image (at `textAt`, or the nearer side edge) with leader lines; below it the markers carry letters and the labels are a lettered list under the image. Works for a raster image and for an SVG.
- **sequence.** Frames in order as a row of same-size cells (the first may be art-directed), optional caption below.
- **detail-grid.** Same-size cells with an optional text each; auto-fit columns of 14rem or more.
- **principles-list.** Title and text side by side from 40rem, stacked below.
- **outcome-montage.** Same-size cells: one column, two from 30rem, three from 50rem; optional text below.
- QA: `[CASE_ID=example] node tests/case/blocks-check.cjs [report.json]` (default `jane`) (320–1920, FR and EN, columns and cell sizes of every grid, annotation layout, chapter intro size, container test) and `node tests/case/blocks-screenshots.cjs <dir>` (blocks and five whole chapters).

## Checks: draft and publish

| Check | When | Fails on |
| --- | --- | --- |
| General (`validateCaseFormat`) | always: `npm run content:check`, `content:build`, so also before `npm test` and CI | broken structure: unknown block or field, wrong image count, name not kebab-case or wrong chapter, crop outside the image, FR approved before EN, a draft without `noindex` |
| Publication (`validateCasePublication`) | `content:check` for cases with `"status": "publish"`; on demand `npm run case:publish-check -- <id>` | any `placeholder: true`, any missing EN or FR text, missing approval, empty chapter, missing image file |

A draft (Jane now) therefore passes `content:check`, `npm test` and CI, and `case:publish-check` lists everything still missing. Tests: `npm run test:case-format`.

## Publishing a case

Only on Kamila's command: `npm run case:publish-check -- <id>` passes → set `"status": "publish"` and `"robots"` without `noindex` in `content/cases.json` → `npm run content:check` → `npm run content:build`.
